预计时间：**5–10 分钟**。你最终只需要准备 5 项：**Account ID、Bucket、Access Key ID、Secret Access Key、公开访问域名**。

<Aside type="tip" title="适合谁">
第一次接触对象存储、博客/Markdown 图片、希望降低公网流量成本的用户可以优先从 R2 开始。
</Aside>

## 1. 创建账号与 Bucket

<Steps>
1. 注册或登录 Cloudflare，打开 **R2 Object Storage**。
2. 创建一个 Bucket，例如 `images`。Bucket 名称是“装图片的容器”，以后通常不需要频繁修改。
3. 记下 **Account ID** 和 Bucket 名称。
</Steps>

## 2. 配置公开访问

上传成功不等于别人可以打开图片。你还需要一个公网访问入口。

推荐顺序：

1. 已有域名：给 R2 Bucket 绑定 **Custom Domain**，例如 `img.example.com`。
2. 仅测试：可使用平台提供的公开开发地址（若你的账户当前提供）。

桌面端的 **公开访问域名** 填最终给别人访问图片使用的前缀，而不是 S3 API Endpoint。

## 3. 创建最小权限凭据

在 R2 的 API Token / S3 凭据页面创建一组只用于当前 Bucket 的凭据。至少需要对象读取和写入权限；如果要在 Publisher 中删除远端资源，还需要删除对象权限。

你会得到：

- Access Key ID
- Secret Access Key

Secret 只显示有限次数时，请立即保存到密码管理器。**不要把 Secret 粘贴到教程网页、聊天记录或公开仓库。**

## 4. 在 Publisher 连接

进入 **云端 → 添加存储 → Cloudflare R2**，填写：

- 显示名称：任意，例如 `我的 R2`
- Account ID
- Bucket
- Region：默认 `auto`
- Access Key ID
- Secret Access Key
- 资源目录：可留空，或填写 `assets`
- 公开访问域名：例如 `https://img.example.com`

点击 **测试并保存**。凭据只进入操作系统凭据库，SQLite 不保存 Secret 明文。

## 5. 第一次发布

左侧导航进入 **发布**，拖入一张图片。应用会自动维护默认上传链（Resize / 命名 / 目标云端），不需要先创建“方案”才能上传。成功后进入 **资源** 查看公网 URL，并可自动复制 Markdown；想核对文件是否真的在 Bucket 里，到 **图库** 刷新一次。

需要多个云同时保存同一张图时，在 **云端** 把 R2 与其他 Storage 组成一个 Storage Group，而不是另建一套上传逻辑。

## 常见问题

### 测试连接出现 401 / 403

通常是 Access Key/Secret 错误、Token 没有当前 Bucket 权限，或 Bucket 名称不匹配。先回控制台检查凭据范围。

### 上传成功但预览打不开

这通常不是上传失败，而是 **公开访问域名** 配置错误。确认该域名确实能直接访问 Bucket 中的对象。

### URL 出现重复目录

Storage 的“资源目录”和 Recipe 的重命名模板都会参与最终路径。若出现 `assets/images/...`，按你的需求保留其中一层即可。

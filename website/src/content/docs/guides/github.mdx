## 创建并确认仓库

<Steps>

1. 登录 [GitHub](https://github.com/)，右上角 **＋ → New repository**。仓库名可用 `my-images`，需要对外分享图片时选择 **Public**。勾选 **Add a README file** 后创建，确保已有初始分支。
2. 已有仓库直接打开即可，不要重复创建。地址例如 `https://github.com/your-name/my-images`，记录 Owner=`your-name`、仓库名=`my-images`。
3. 从仓库文件列表左上角的分支菜单确认分支，例如 `main`。不能把网页地址中的 `tree/main` 整段填进分支。

</Steps>

## 创建最小权限 Token

<Steps>

1. 打开 [Fine-grained personal access tokens](https://github.com/settings/personal-access-tokens)，点击 **Generate new token**。
2. 填名称“Mirror Cloud”，设置过期时间。**Resource owner** 选仓库所属用户或组织；组织可能要求管理员批准。
3. **Repository access → Only select repositories**，只选图床仓库；**Repository permissions → Contents** 选 **Read and write**，Metadata 保持系统必需的读取权限。无需勾选工作流、账号管理等权限。
4. 生成后立即复制令牌，填入镜云“访问令牌”。令牌不是 GitHub 密码或 SSH 密钥；不要把它放进仓库、网址或教程截图。

</Steps>

## 在镜云逐项填写

打开 **云端 → 添加存储 → GitHub**，按实际仓库替换示例。

<ConfigurationFields provider="github" />

点击 **测试并保存**。应用会校验仓库与分支访问；保存后在云端列表将其设为默认发布目标。

## 上传并确认结果

<Steps>

1. 在 **发布** 选择一张测试图并提交，等任务完成。
2. 到 GitHub 仓库检查 `assets` 下是否出现图片和提交；到镜云 **图库** 刷新。
3. 到 **资源** 复制 URL，未填写自定义域名时通常是 `raw.githubusercontent.com` 地址。用未登录的浏览器打开，再测试复制 Markdown 到文档。

</Steps>

<Aside type="caution" title="公开仓库与私有仓库">
Token 能写私有仓库，不代表访客能看图片。私有仓库需要自己的公开代理/CDN才能提供永久公开链接。仓库适合文档和轻量资源，外链访问也受网络与平台策略影响。
</Aside>

## 常见错误

| 现象 | 检查及处理 |
| --- | --- |
| 401 | Token 是否过期、撤销、粘贴不完整 |
| 403 | Token 是否包含当前仓库和 Contents 写权限；组织批准、分支保护是否允许操作 |
| 404 | Owner、仓库名、分支是否准确；私有仓库授权失败也可能返回404 |
| 空仓库无法保存 | 先在 GitHub 初始化 README，确认分支存在，再添加 |
| 409 / 并发写入 | 同一分支可能被其他客户端修改，稍后重试，避免同时批量提交 |
| 已上传但图片打不开 | 分别检查仓库公开性、Raw 访问网络与自定义域名，不能只看“测试成功” |

参考：[GitHub 官方 Token 管理](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)、[创建仓库](https://docs.github.com/en/repositories/creating-and-managing-repositories/creating-a-new-repository)。本网站不接收密钥。

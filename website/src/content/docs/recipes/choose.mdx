description: 先上传成功，再决定是否需要压缩、转换或保留原图。
---

镜云 v1.4 不要求普通用户先创建“方案”或 Recipe。第一目标是让默认上传链稳定地把图片写入目标云端。

## 推荐顺序

1. **先用默认处理链完成一次真实上传**；
2. 确认任务成功、图库能看到远端文件、资源页能复制公网 URL；
3. 再根据用途调整 Resize / Format / Quality / Rename；
4. 多云可靠性通过 Storage Group 配置，不通过另一套“方案”概念配置。

## 常见取舍

- **文档截图**：优先清晰度，避免过度压缩文字边缘；
- **博客配图**：可适度缩放和 WebP 压缩，兼顾体积与观感；
- **分享图**：更重视体积与加载速度；
- **原图归档**：不做有损转换，只统一远端命名和存储位置。

## 不确定时怎么办

保持默认值即可。处理链是内部实现细节，不需要为了使用镜云先理解完整的 Workflow 模型。

如果你启用了插件，插件会在远端上传成功后按已授权的 Hook 执行；插件失败不会把已经成功上传的图片回滚。

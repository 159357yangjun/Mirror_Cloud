## 先选策略

| 策略 | 行为 | 适合 |
| --- | --- | --- |
| Mirror All | 向多个目标并行发布 | 每个目标都需要保存副本 |
| Primary + Backups | 主存储优先；镜像始终同步，备份在主存储失败时接管 | 主要使用一条公开链接，同时保留备用目标 |

## 配置与验证

<Steps>
1. 在**云端**分别添加并测试需要的连接。
2. 建立多云组，选择策略与成员角色。公开发布的主目标要有可访问的公开地址。
3. 将多云组设为默认发布目标，上传一张图片。
4. 在**资源**核对每个副本的成功 / 失败状态，并在对应云端查看文件。
</Steps>

## 部分失败怎么处理

先从**任务**检查权限、网络或配置错误，修正后在**资源**找到异常卡片，点击“修复副本”。应用可读取健康远端副本，重建失败副本，不要求本地保留原图。所有副本都不可读时，没有可用修复来源，需重新提供文件。

备份接管取决于发布结果；它不代表已经发布的公开链接会自动切换域名。

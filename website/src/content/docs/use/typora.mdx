## 开始前

在镜云连接可写云端并设置默认目标，先在**上传**手动上传一张图片，确认公开链接可用。Typora 需要公开 URL，不能使用 R2 / S3 私有目标；无需手动创建 Workflow。

## 配置一次

<Steps>
1. 打开 **设置 → 快捷集成 → Typora 集成**，点击“重新检测”，确认桥接命令已生成。
2. 点击 **复制命令并打开 Typora**。镜云复制命令并启动 Typora，不会修改它的偏好设置。
3. 在 Typora 打开 **偏好设置 → 图像**，上传服务选择 **Custom Command / 自定义命令**。
4. 粘贴命令，点击 **Test Uploader / 验证图片上传选项**。
5. 回到镜云的**任务**检查记录，在**云端文件**核对远端文件；确认 Typora 图片已替换为可打开的公网链接。
</Steps>

## 以后怎么使用

在 Typora 插入本地图片并执行上传即可。镜云统一维护缩放、转换、命名、默认云端、多云策略和已启用插件；切换默认目标通常不用重配命令。主窗口不必一直显示，桥接使用同一份配置与凭据。

## 跨设备显示图片

上传成功表示文件已写入云端。其他设备还需要能在未登录图床的情况下打开 Markdown 中的图片 URL。若用于分享，优先使用在读者网络中可达的公开 HTTPS 图片域名，例如 [R2 公开桶的自定义域名](../../guides/r2/)。用另一台设备或不同网络打开实际图片链接，确认它返回图片。仓库原始文件地址的可达性取决于仓库服务及读者所在网络。

在已经使用网络图片的文档中，可以在 Typora 的图像偏好设置里仅对本地图片应用自动上传。复制或分享时请保留图片的完整 URL。

## 常见错误

| 现象 | 处理 |
| --- | --- |
| 仍显示 PicGo(app) | 上传服务尚未切换到 Custom Command |
| 命令失效 / 移动了安装位置 | 重新检测并复制命令，不手动猜安装路径 |
| 401 / 403 | 检查图床凭据与写权限；GitHub Token 需 Contents: Read and write |
| 私有目标无法返回链接 | 更换为可产生公开 URL 的默认目标 |
| 已上传的网图又显示 `Image file does not exist` | 使用“上传所有本地图片”，或关闭对网络图片应用自动上传 |
| 显示成功但图片打不开 | 从另一网络匿名打开完整图片链接，确认公开域名和读取策略 |
| 插件警告 | 到**插件**查看配置、授权与执行记录 |

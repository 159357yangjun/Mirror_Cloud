# 桌面与教程站二次元风格设计稿

日期：2026-10-29。用户已确认范围：桌面应用和教程网页都改。建议视觉方向为「晴空樱花」，本文供实施前审阅，尚未修改产品界面。

## 目标与候选方向

推荐「晴空樱花」：以动漫天空插画、浅蓝背景、樱粉强调和深蓝文字构成清爽工作台，插画作为局部氛围，表单、状态、表格保持清晰。另有「夜樱深色」（更强夜间氛围）和「轻量动漫」（只调整配色与横幅）两种备选；实施前确认推荐方向。

保留 React/Tauri 与 Astro/Starlight 技术栈、七页导航和现有操作流程，不新增组件框架、字体包或动效依赖。重构任务继续保留，不能将这次美化当作此前三批结构统一已全部完成。

## 共用视觉与素材

- 主色使用晴空蓝与樱粉，正文使用深蓝灰；危险、成功、警告仍使用原语义颜色，不能用粉色掩盖失败。
- 以已有 CSS 变量管理颜色与玻璃表面，减少新增硬编码颜色。保留明暗主题、键盘焦点、缩放和 reduced-motion 支持。
- 插画选择动漫风景或天空，不使用无来源的人物贴图遮挡操作。优先采用已核实授权的 Sky Backgrounds，作者 Unicorn Creates，CC BY 4.0，需要署名。
- 素材来源：https://unicorncreates.itch.io/sky-backgrounds 。下载后保留来源、作者、许可与具体文件对应关系；桌面和站点使用本地打包素材，展示不依赖外部图床在线加载。
- 不把搜索缩略图、站点宣传拼图当作可直接分发的原图；只使用实际授权下载的素材。下载压缩包等一次性中间文件用后立即删除。
- 桌面与网页共用同一幅主视觉和色彩语言；网页的素材路径通过 Astro base 处理，不硬编码根路径。

## 桌面应用

1. 保留已有雾白、深夜、樱粉设置及用户保存的选择；升级樱粉的视觉表现，并在皮肤面板提供明确的动漫风景预设。首次打开的视觉与已有用户偏好迁移，在实施计划中明确，不强制覆盖存量壁纸。
2. 侧栏品牌区增加轻量云朵/樱花图形，选中态、快速发布按钮和底部信息统一层级，保持现有导航、版本提示和帮助入口。
3. 发布页加入有实际用途的风景欢迎区与清楚的上传入口，状态信息、目标选择、任务和最近资源保持可见；装饰不能替代错误提示或前置条件。
4. 资源、图库、云端等页面通过统一表面、标题和控件样式接入，不逐页增加整屏人物背景；桌面数据操作、凭据、更新与云端权限逻辑保持原样。
5. 壁纸预设使用受控资源标识，不把任意 file/data/javascript 路径放进 CSS。原有用户 http/https 壁纸输入保持兼容。

## 教程网站

1. 首页改为插画主视觉、明确的「开始使用」、七类图床快速入口和常用教程卡片，保留原首页内容的可访问路径及四步发布流程。
2. 新增 Starlight 自定义样式，统一导航、侧栏、文章标题、提示框、步骤和代码块，适配手机和深色模式。
3. 保留 R2、S3、OSS、COS、GitHub、Gitee、WebDAV 与发布、Typora、多云、Local API、安全等现有教程路线，不做无实际目标的链接。
4. 按现有应用表单检查关键教程描述，优先更正 R2 向导/公开与私有模式的落差，以及公开域名和 API Endpoint 的区别。网页不要求录入任何密钥。
5. 已实测教程新旧项目地址及 R2 页面返回 HTTP 404；源码文档契约通过不表示线上可用。404 原因须核对 Pages 的实际设置和部署 URL，不只根据仓库名称推断。
6. 本轮先完成站点代码和可运行预览。更改远端 Pages 设置、推送或部署须遵循用户已有授权；未完成时明确报告线上仍未恢复，不能把本地预览称为上线。

## 实施顺序与验证

阶段一：确认视觉设计、获取授权原图并完成共享素材记录。

阶段二：桌面样式/樱粉预设/侧栏与发布页，验证真实组件、主题切换、用户偏好兼容、不同窗口大小、文本可读性和关键点击流程。

阶段三：教程首页与文章主题、手机布局和教程内容一致性，运行现有文档契约；依赖已有时执行站点 build，没有依赖时不隐式安装，交云端流程验证。

阶段四：整体差异审查、本地提交、说明对应源码的云端验收缺口；远端操作按授权执行。

现有检查包括 desktop build、test:unit、check_contracts.py、check_user_flow.py、check_docs_site.py 和相关浏览器测具。涉及主题计数变化应记录原因及实际覆盖，不能仅重签基线消除原有 11 行漂移；修改带指纹的测具须保留 HEAD/工作区核验并在提交后复核。

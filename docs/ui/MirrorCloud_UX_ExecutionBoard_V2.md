## C. main-only 提交、验收与多 Agent 协作（2026-10-20 起生效）

- **唯一后续开发主线为 `main`**。用户禁止再创建 feature/QA/integration/release 等新分支；历史分支仅可用于剩余成果核对、PR 收口，成果进入 main 并通过 CI 后及时删除（需 GitHub 删除权限/操作）。
- **保护规则阻塞必须显式升级**：当前 main 强制 Pull Request，不能靠新建分支规避用户决定，也不得直接 force push / 关闭 CI。新功能需要写入而规则仍未调整时，先由仓库维护者决定是否允许受控直接更新 main，期间可做只读审计、设计和 CI 证据汇总。
- 存量 PR #40、#43 已完成 main 合并；PR #41（UI-00）和 #42（UI-01）作为**历史遗留已存在分支的收口事项**处理，绝不从这里衍生新分支。
- **串行主线写入**：先复核最新 main SHA → 只修改授权的具体文件 → 运行局部测试 → 全 CI → 按完整 SHA 汇报 → 下一个任务。不同 AI 可并行做只读评审、代码建议和离线测试，但严禁同时向 main 的同一文件写入。
- 不建立“一项任务对应一个新分支”的模板；任务划分体现在 `docs/ui` 工作包、GitHub Issue、Commit 说明及状态机，而不是 Git 分支。
- UI-02 共用组件合同、UI-03 资源、UI-04 任务、UI-05 云端、UI-06 图库、UI-07 插件、UI-08 设置、UI-09/10 G3 验收都按上述规则串行推进。
- 旧分支不得因 Git Compare 显示 ahead 而直接删除：受保护 main 的 Squash 合并不保留原 SHA 祖先关系，需比较最终**文件树与独立成果**，并保留 CI 工件与 PR 记录。

## E. 每个工作包的统一 Definition of Done

**提交前**

- [ ] 远端 HEAD、PR 状态、待改文件重新核对；列出禁止更改的契约和危险 mutation。
- [ ] 交付本批的 G0 任务与失败路径；G1 wireframe、对象定义和屏幕状态表；严格验证 TaskUI（适用时）。
- [ ] 对新手路径与高级入口分别给出“什么默认展示、什么可以展开、无数据时怎么说”。

**代码实现**

- [ ] 仅按现行 main-only 策略提交；禁止新建任何分支。main 仍需 PR 时暂停写入并请求维护者调整保护，禁止绕过；关键 API/Rust 权限/数据库未隐式改写。
- [ ] 对加载/空/错误/部分/未知/取消/成功状态都有实际可观察行为。
- [ ] Secret、Token、签名参数不得出现在原始错误通知、React DOM、导出日志或 CI Artifact。
- [ ] 危险操作证明“取消时调用计数 0”，网络状态未知重试要阻断或提醒核对。
- [ ] 没有硬编码演示图片、示例云已连接标识、伪造的任务成功率和进度。
- [ ] 新增测试以**真实产品组件**为被测对象；模拟后端必须明确测试性质。

**验收输出**

- [ ] 同一 Git SHA 的 TypeScript/Vite、Rust（如适用）、浏览器和现有用户流程 CI 全绿；如未完成标为运行中。
- [ ] Windows 640×480、1024×768、1366×768、1440×900；100/125/150% 系统 DPI 的原生 GUI 证据（每批按风险选覆盖，最终 UI-09 全面覆盖）。
- [ ] 键盘 Tab/Shift+Tab、焦点返回、Esc、滚动、长中文/长文件名、亮暗主题和错误恢复回放。
- [ ] 安全和可用性测试给出**失败反例与修复提交**，不能只展示成功路径。
- [ ] 写入 CI URL、截图/日志 Artifact、测具版本、比较的冻结 SHA 和剩余 BLOCKER。
- [ ] 对已知未通过的门禁作出 PASS / HOLD / FAIL 明确裁决；G3 与发行门不得互相代替。

## F. 用户要求的逐 Commit 修改交付模板

每一次 Commit 之后立刻给用户一份记录；每一批最终再汇总一份。**不能只给“已修改 13 个文件”这种无法回溯的概述。**

```markdown
### COMMIT 01 — <简短标题>
- 目标：main（如 main 分支保护要求 PR，明确记录 BLOCKED 与维护者处理结果；禁止新建临时分支）
- Commit：<完整40位SHA>  |  Diff：<具体commit URL>
- 文件清单（完整路径、A/M/D）：
  - M apps/desktop/src/pages/AssetsPage.tsx
  - A apps/desktop/src/features/assets/AssetInspector.tsx
- 为什么改：用户任务 / 复现步骤 / 原问题证据。
- 前 → 后（核心代码）：选 1–3 处真实 diff，不能写拟议伪代码充数。
- 影响面：UI、API、云对象/资产语义、安全权限、数据迁移是否变化。
- 验证：测试脚本/CI run id/明确结果（PASS、FAIL、RUNNING、NOT RUN）。
- 阻塞：未验证项及负责人，若失败则指向一手日志及修复 commit。
```

PR 汇总必须给出 `git diff --stat` 对应的全部路径、commit 数、每条 CI 的 SHA/结论、是否满足 main 门禁并可验收；不得声称已发布。**合并要有明确授权；Draft 关闭与合并是不同操作。**

## G. 下一步立即可执行的四个动作（main-only）

1. **审阅已合并 PR #40 / #43 的真实 main CI**：R2 UI 已在 main，仍需保留真实权限/匿名访问的受保护 E2E；不能把 UI CI 当 live R2 已验证。
2. **收口历史 UI-00 #41 / UI-01 #42**：以现有 PR 为唯一过渡入口，解决审查意见、通过当前 HEAD CI，不创建新分支；完成后由维护者删除已无独立内容的旧分支。
3. **冻结 UI-02 共享错误/教程/导航上下文合同**：先验证可运行的发布→资源→任务样板；不暗改后端权限与迁移。
4. **先打通 T1/T2/T3 主路径再做其它页面**：危险远端操作必须先定义取消、未知结果、安全重试，并用 Windows 原生证据验收。

**保持的边界**：禁止新建分支，禁止强推 main 或关闭保护性 CI，禁止用正式 Release Tag 测试；未授权不连接真实 Cloudflare、不改密钥权限、不削弱 R2 protected E2E。清理分支必须在内容真正进入 main 后执行，并出具删除前后 ref 核对。

## C. PR / 分支切分与多人协作

- 所有产品 UI PR 从**已验收的隔离集成分支**创建；不能直接变更 `main`、`dev`、发布标签或原冻结候选。
- `ui/full-ux-00-audit`：七页 G0 实际任务+截图/术语/风险，**只文档**。
- `ui/full-ux-01-system`：G1 IA、Tokens、最小共享壳层/诊断合同；共同组件归本分支，其他 AI 等合约冻结。
- `ui/full-ux-02-assets`：AssetsPage + AssetInspector + 对象操作测试。
- `ui/full-ux-03-tasks`：TasksPage + TaskProblemResolver + 不可安全重试反例。
- `ui/full-ux-04-storages`：StoragesPage + R2 PR #40 收口与其他 Provider 检查；注意 PR #40 的未合并冲突。
- `ui/full-ux-05-gallery`：GalleryPage + GalleryInspector；远端对象语义隔离。
- `ui/full-ux-06-extensions`：PluginsPage + PermissionReview + AI 配置。
- `ui/full-ux-07-settings`：SettingsPage 拆分/设置组/迁移保持原状态机。
- `qa/full-ux-08-windows`：只增加 Windows/浏览器测试仪器、截图与真实 G3 报告，不让 QA 分支偷偷含产品重构。
- `ui/full-ux-09-acceptance`：集成差量回归/门禁判断，修复单独 PR 而不是一次“大合并”。

**并行规则**：共享 `AppShell`、`styles.css`、`project.taskui.json`、全局 Confirm/Toast/error contracts 的写入由 UI-01 负责；各页面在稳定接口下开发。另一个 AI 可只读交叉审查、跑 CI、验证 screenshot、复核 diff，不在同一分支并发改相同文件。

## D. G0/G1 任务追踪与 UI 映射

| 任务编号 | 用户目的 | 页面组合 | 关键反例 |
|---|---|---|---|
| T1 | 首次连接云端并发布 | 发布→云端→发布→任务→资源 | 无桶/缺密钥；私有不可公开；未知结果 |
| T2 | 搜索资源并分享 | 资源→详情 | 链接未公开/过期；复制失败 |
| T3 | 定位并恢复失败任务 | 任务→云端/资源→任务 | 部分成功、重复上传、权限拒绝 |
| T4 | 浏览/维护远端文件 | 图库→目录/预览→对象操作 | 删除取消、批量混桶、名称冲突 |
| T5 | 管理连接和存储组 | 云端→目标设置 | 权限误判、连接失败、API Endpoint 与公网 URL 混淆 |
| T6 | 启用插件或 AI 工作流 | 插件→权限→运行记录 | 过宽网络/密钥权限、撤权失败 |
| T7 | 配置输出和 Typora | 设置→发布 | 配置生效不清、错误命令例子 |
| T8 | 导出/导入配置与迁移 | 设置→预览→激活 | 映射冲突、部分恢复、不可撤销 |
| T9 | 检查更新及升级 | 设置→更新 | 下载 ≠ 安装 ≠ 成功升级，回滚需单独门禁 |
| T10 | 在帮助中定位错误后续做 | 任一页面→情境教程→返回 | 帮助关闭后丢失原输入/对象/目录 |

任务名称、频率和完成率仅是拟定。UI-00 必须通过用户访谈/真实任务回放修订；`project.taskui.json` 修改后跑仓库严格检查，并保存输出证据。

## E. 每个工作包的统一 Definition of Done

**提交前**

- [ ] 远端 HEAD、PR 状态、待改文件重新核对；列出禁止更改的契约和危险 mutation。
- [ ] 交付本批的 G0 任务与失败路径；G1 wireframe、对象定义和屏幕状态表；严格验证 TaskUI（适用时）。
- [ ] 对新手路径与高级入口分别给出“什么默认展示、什么可以展开、无数据时怎么说”。

**代码实现**

- [ ] 仅在授权的隔离分支；一 PR 一语义范围；关键 API/Rust 权限/数据库未隐式改写。
- [ ] 对加载/空/错误/部分/未知/取消/成功状态都有实际可观察行为。
- [ ] Secret、Token、签名参数不得出现在原始错误通知、React DOM、导出日志或 CI Artifact。
- [ ] 危险操作证明“取消时调用计数 0”，网络状态未知重试要阻断或提醒核对。
- [ ] 没有硬编码演示图片、示例云已连接标识、伪造的任务成功率和进度。
- [ ] 新增测试以**真实产品组件**为被测对象；模拟后端必须明确测试性质。

**验收输出**

- [ ] 同一 Git SHA 的 TypeScript/Vite、Rust（如适用）、浏览器和现有用户流程 CI 全绿；如未完成标为运行中。
- [ ] Windows 640×480、1024×768、1366×768、1440×900；100/125/150% 系统 DPI 的原生 GUI 证据（每批按风险选覆盖，最终 UI-09 全面覆盖）。
- [ ] 键盘 Tab/Shift+Tab、焦点返回、Esc、滚动、长中文/长文件名、亮暗主题和错误恢复回放。
- [ ] 安全和可用性测试给出**失败反例与修复提交**，不能只展示成功路径。
- [ ] 写入 CI URL、截图/日志 Artifact、测具版本、比较的冻结 SHA 和剩余 BLOCKER。
- [ ] 对已知未通过的门禁作出 PASS / HOLD / FAIL 明确裁决；G3 与发行门不得互相代替。

## F. 用户要求的逐 Commit 修改交付模板

每一次 Commit 之后立刻给用户一份记录；每一批最终再汇总一份。**不能只给“已修改 13 个文件”这种无法回溯的概述。**

```markdown
### COMMIT 01 — <简短标题>
- 分支：ui/full-ux-xx-topic
- Commit：<完整40位SHA>  |  Diff：<具体commit URL>
- 文件清单（完整路径、A/M/D）：
  - M apps/desktop/src/pages/AssetsPage.tsx
  - A apps/desktop/src/features/assets/AssetInspector.tsx
- 为什么改：用户任务 / 复现步骤 / 原问题证据。
- 前 → 后（核心代码）：选 1–3 处真实 diff，不能写拟议伪代码充数。
- 影响面：UI、API、云对象/资产语义、安全权限、数据迁移是否变化。
- 验证：测试脚本/CI run id/明确结果（PASS、FAIL、RUNNING、NOT RUN）。
- 阻塞：未验证项及负责人，若失败则指向一手日志及修复 commit。
```

PR 汇总必须给出 `git diff --stat` 对应的全部路径、commit 数、每条 CI 的 SHA/结论、是否准许进入隔离集成分支。**合并要有明确授权；Draft 关闭与合并是不同操作。**

## G0 — 核心任务与对象（频率均为待实测假设）

| 任务 | 起始条件 | 用户操作与可观察完成条件 | 风险/恢复 |
| --- | --- | --- | --- |
| T1 首次发布一张图片（假设 high） | 未配置或已配置云端 | 若未配置，转云端连接后返回；在发布区选择文件/URL/剪贴板；打开已有 UploadDialog 核对文件与目标，再提交；在任务/资源中看到对应结果 | 未配置禁用理由、上传状态不确定时先查任务、仅重试失败项 |
| T2 查找并复制已发布图片链接（假设 high） | 已有发布记录 | 从发布区最近记录或「资源」找到对象；复制公开链接，或对私有对象显式生成临时分享链接；看到反馈 | 不把「已上传」冒充「可匿名访问」，失败时明确反馈 |
| T3 定位并恢复失败任务（假设 medium） | 任务存在失败/部分失败状态 | 从发布区最近任务或「任务」查看失败原因；根据情况重试/修复；在任务及资源中核对新状态 | 防重复提交、确认历史成功项不重复上传、不可恢复情况明示 |

核心对象：Storage/Storage Group（发布目标）、Workflow（处理配置）、Asset（本地发布索引）、StorageEntry（远端真实文件）、Task（后台运行/历史状态）。**Asset 与 StorageEntry 不合并数据语义**。

## G1 — 信息架构与入口决定

- 首批保留现有七个顶层入口：发布 / 资源 / 云端 / 图库 / 插件 / 任务 / 设置；不添加假功能「全局搜索」或未接线的「工作流」页面。
- 发布为主工作区：左侧「选择图片 → 在 UploadDialog 核对 → 提交」；右侧为真实的当前发布目标与链接输出偏好；下方「最近发布 / 最近任务」按需切换。未提交前不展示伪进度条。
- 存储目标设置为对象配置，可从发布区快速切换，并进入云端完成复杂配置；一旦切换失败显示错误，绝不能默默假设完成。
- 高频对象操作保留在「资源」「图库」对应对象上。批量操作归「图库」选择状态；危险删除仍需确认。
- 首屏不叠加第二组与上传等价的大入口；剪贴板/URL 为当前上传流程的来源选择，继续复用 UploadDialog。
- 窄窗口侧栏收缩成图标轨道时，**可发现性与可访问名称**不可丢：保留 title/aria-label/aria-current、可见焦点；不为此添加第二套导航。
- 「最近发布」「最近任务」属辅助信息，可以切换呈现，不常驻挤占发布区高度。
- 目前不改变页间状态存储机制；资源筛选/图库目录恢复由后续 G0/G1 专题决定，避免未经批准进行全局状态迁移。

## G1 设计决策记录

1. 不照搬设计图里额外的「存储配置」「工作流」独立顶层页面：当前业务代码不支持等价七入口，硬改会制造死入口。
2. 不为「立即发布」新增一条独立后端路径：现有 UploadDialog 处理输入、失败重试和上传结果，是单一事实来源。
3. 右侧呈现当前目标的编辑入口，而不是假造三云都「已连接」；没有真实数据时使用空状态和添加云端入口。
4. 把辅助结果区域置于主上传区之后，减少常驻重复信息。
5. 保留既有主题、Tokens、危险操作确认与更新器含义；本轮只修用户当前认可布局中最明确的可用性问题。

## G2 变更范围

- `apps/desktop/src/pages/PublishPage.tsx`：主任务与辅助配置层级优化，最近活动区域不再常驻侧栏。
- 不修改 `Cargo.*`、Tauri 配置、数据库、API、云权限、版本号、锁文件和受保护 R2 测试。

## G3 回归任务（均需在目标端实际执行）

1. Windows 1366×768：无云端→设置默认云端→发布测试图片→进入任务→到资源复制链接；记录操作路径与输入方式。
2. Windows 640×480、100%/125%/150% DPI：导航图标可悬停识别、Tab 可访问、焦点可见；上传区无遮挡，缩放仍可操作。
3. 发布区切换不同现有云端，等待后端成功再看到实际已选目标；模拟失败必须可见；剪贴板/URL/拖放都走同一 UploadDialog。
4. 最近活动两个视图的空、加载、失败、成功状态；页面切换再返回、弹窗取消及键盘焦点恢复。
5. Windows GUI、真实云服务和升级回滚 **未执行前必须填「未验证」**。前端静态 CI 通过不等于 G3 通过。

G0 三个任务已建模，G1 导航与工作区布局形成可追溯人工方案；**尚未建立本项目 `project.taskui.json` 的严格机器校验，不宣称 TaskUI G1 strict PASS**。本隔离分支的 UI 代码只是 G2 试验候选，必须在 CI、实际截图、键盘和任务验收后才考虑进入正式集成链。

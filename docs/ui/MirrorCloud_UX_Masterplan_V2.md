## 1. 产品目标与用户类型

### 1.1 北极星目标

**让第一次使用镜云的人，在不知道 Bucket、S3 Endpoint、插件权限和任务队列原理时，也能找到正确入口、完成操作，并在出错时根据软件引导安全恢复。**

五条不可妥协的原则：

1. **任务先于页面**：先问用户在做什么，再决定入口、步骤和对象操作；不要为了铺满界面增加统计卡片或“全部功能”入口。
2. **对象与证据优先**：上传结果、部署副本、云端实际对象、后台任务必须显示各自真实状态，不能把“请求入队”“已写入”“可公网访问”混为一谈。
3. **预防优于报错，恢复优于错误码**：格式预检、先验条件提示、保留输入、定位原因和下一步引导为一条完整链路。
4. **渐进披露**：新手只有当前一步和可执行的下一步；高级选项不丢失，但默认折叠，不占首屏。
5. **操作可核查且安全**：成功必须有可验证证据；写入、删除、权限改变、未知状态重试不得静默发生。

### 1.2 用户画像（假设，实施前访谈验证）

| 类型 | 核心任务 | 优先解决的障碍 |
|---|---|---|
| 首次使用者 | 配一项云存储 → 发布一张图片 → 复制链接 | 不懂术语、无法判断配置是否完成、帮助入口找不到 |
| 日常上传者 | 拖放批量图片 → 核对目标 → 获得发布结果 | 频繁跨页、进度和结果混淆、重复点击 |
| 资源维护者 | 找图 → 看副本/健康度 → 分享/修复/删除 | 资产索引和真实云端对象关系不清、操作远离对象 |
| 排障用户 | 定位失败任务 → 判明可否重试 → 恢复 | 错误信息笼统、日志过长、误将未知状态重复提交 |
| 进阶用户 | 存储组、插件、集成、备份/迁移 | 复杂配置与安全设置混在一起，影响日常操作 |

## 2. 总体信息架构：保留七个主入口

本轮**不先改导航数量、不新建无后端的独立“工作流”页**。先把现有七入口做对，再用任务回放决定是否需要合并。标签建议：

```text
镜云
├─ 发布         选择来源 / 目标 / 处理方式 / 发布反馈
├─ 资源         已发布资源索引 / 副本状态 / 公开或私有分享 / 修复
├─ 云端         连接与健康状态 / 存储组 / 发布目标 / 配置诊断
├─ 图库         真实云端文件 / 目录 / 预览 / 移动 / 下载 / 删除
├─ 任务         上传/同步/修复作业 / 失败原因 / 安全恢复
├─ 插件         已安装 / 商店 / 权限 / AI 能力及其配置
└─ 设置         通用 / 外观 / 复制与输出 / 集成 / 数据迁移 / 更新与诊断
全局入口：快速发布（唯一），帮助与情境教程，状态/通知，确认框。
```

### 2.1 页面之间的闭环，而不是孤岛

- **首用**：发布空状态 → 云端配置向导 → 设置目标 → 返回原发布任务（保留来源/草稿）→ 发布 → 任务 → 资源验证。
- **管理**：资源列表选图片 → 对象详情 → 部署副本 → 公开链接或私有时效链接 → 复制反馈。
- **真实远端维护**：资源有远端定位信息时允许跳转图库相应位置；反方向仅在能确认归属时显示“对应发布记录”。**不能按同名猜关联**。
- **失败恢复**：任务记录 → 错误说明 → 到相关云端/资源的确切字段或副本 → 回任务复测/安全重试。
- **教程跳转**：从错误位置打开当前帮助，再返回**同一页面、同一对象、同一字段**，而非重新从首页开始。

### 2.2 共享壳层与布局断点

```text
┌─ 左导航：全宽 220px / 紧凑图标轨（原入口保留） ─┬─ 页面工作区 ───────────────────────────────────┐
│ 产品名 / 快速发布                               │ 标题 + 当前任务说明 + 页面级唯一主操作            │
│ 七入口；当前项及未处理任务真实标识               │ [对象工具条：搜索/筛选/排序/视图]                │
│ 帮助 / 外观 / 版本提示                           │ [主对象列表/主工作区] [按需对象详情/配置侧栏]     │
│                                                  │ [空、加载、部分成功、错误与恢复状态]              │
└──────────────────────────────────────────────────┴────────────────────────────────────────────────┘
```

- 在 1440×900、1366×768、1024×768 下优先保证主工作区；640×480 使用可收纳导航、纵向布局/侧栏抽屉，**不容许水平内容被遮蔽**。
- Windows 100%、125%、150% **系统 DPI** 实测和 Edge DPR 模拟分别记录；不能互相冒充。
- 鼠标目标建议至少 44×44 CSS px（如空间不能满足则专门留有键盘等价路径和可见命中区证据）；键盘焦点明显、Tab 可达、弹窗 Esc/焦点锁定/返回焦点；尊重主题变量与可读对比度。
- 页面切换保留**值得保留**的工作上下文（查询、筛选、图库当前目录和选中对象），需要明确恢复边界；危险批量选择不跨存储桶或账号意外残留。
- 全局 Toast 只负责简短状态通知；可修复错误在对象附近的内联诊断中完成，避免弹窗遮挡工作区。

## 3. 各页面落地方案（对象、主操作、空状态、危险边界）

| 页面 | 工作区组织（主 → 辅助） | 优先实现的完整任务 | 安全与防呆要求 |
|---|---|---|---|
| **发布** | 图片输入区→真实目标摘要→处理/输出选项→最近结果，右侧少量辅助信息 | 首次配置→发布；文件/URL/剪贴板→一次核对→提交；失败回任务 | 未选目标时不要生成“可发布”假态；重复提交和状态未知时先查任务；复用现有 UploadDialog |
| **资源** | 搜索/筛选/视图→已发布资源列表→右侧对象详情及部署副本→对象就地操作 | 找图、复制链接、预览、了解公开/私有、修复失败部署 | “资源索引”不是“所有远端文件”；链接复制需显示权限/失效提示；删除说明影响范围、必要时回退 |
| **图库** | 云端选择→目录树/面包屑→远端文件网格或表格→预览详情 | 找到真实云文件、下载、重命名、移动、批量管理 | 永久删除显示精确桶/目录/数量；批量任务清楚说明异步状态；无默认公开推断；避免非法目录移动 |
| **任务** | 状态筛选→任务队列→选中任务详情/步骤/错误原因→恢复操作 | 失败任务查看证据→修正云端设置→回任务安全重试 | 显示等待/运行/已确认/部分成功/失败/结果未知；未知状态不提供一键无脑重试；只重试允许失败项 |
| **云端** | 连接列表与真实状态→存储组/目标→选中配置详情→逐步诊断 | 新手 R2、GitHub/Gitee 等连接→目标生效→返回上传 | L0 本地检查 / L1 只读探针 / L2 有写入的验证必须分级；目前 R2 后端 test 会临时写入，需同意；不能把“连接通过”当成私有已验 |
| **插件** | 已安装列表→插件详情及权限→可选商店/AI 区 | 安装、配置、授权、关闭及排错 | 授权范围与外发网络/密钥/外部写入明确、可撤销；插件执行失败有日志但不泄密；高级 AI 默认折叠 |
| **设置** | 页内分组导航→本组设置面板→局部检查结果 | 输出格式、Typora/本地 API、快捷键、迁移、更新、诊断 | 每个区独立表单和恢复；迁移两阶段预检后激活；不可把下载更新当成已升级；拆分大组件时保持 API 与状态契约 |

**视觉风格**：延续用户认可的轻量蓝色任务导向、明确主次关系和卡片式对象管理；沿用已有 mist/midnight/sakura 主题机制，采用统一设计 Tokens，而不是引入第二套互相冲突的颜色、按钮、间距系统。参考图的示例图像、云服务状态、数字进度均为演示，不得硬编码进产品。

## 4. 全局防呆与诊断系统：从“报错”升级为“可恢复”

### 4.1 每项关键操作的生命周期

**前置条件 → 输入预检 → 用户核对影响 → 提交与不可重复状态 → 实际结果证据 → 恢复与再验证**。每一步都可中断；关闭教程不应自动提交。

### 4.2 四级检查和权限边界

| 级别 | 能力 | 默认行为 | 明确禁止 |
|---|---|---|---|
| L0 | 本地格式、名称、必填、路径语义、互斥项校验 | 可实时执行 | 不推断远端权限或对象真实存在 |
| L1 | 远端**只读**受控探针 | 仅在实际存在只读后端能力且用户发起时运行 | 不把已有 R2 test_connection 误当只读 |
| L2 | 上传/覆盖/删除/迁移/试写，含临时对象探针 | 提交前披露范围、副作用、残留风险，必须明确确认 | 不后台自动写入、不为诊断开放管理员权限 |
| L3 | 正式云权限/匿名私有验收、升级回滚 | 受保护环境、专用数据和审批，单独存证 | 不用浏览器 Mock/CI 构建替代真实验收 |

### 4.3 统一错误展示协议（目标数据结构，不宣称现有 API 已实现）

```ts
interface SafeProblem {
  kind: 'input'|'auth'|'permission'|'network'|'not_found'|'quota'|'conflict'|
        'partial'|'uncertain'|'unsupported'|'internal';
  operation: string;              // 操作种类，例如 storage.connect / upload.submit
  subject?: {kind:string; id:string}; // 可关联对象（非凭据）
  severity: 'info'|'warning'|'blocking';
  outcome: 'not_started'|'failed'|'partial'|'unknown';
  retrySafety: 'safe'|'requires_check'|'forbidden';
  safeSummary: string;            // 非原始 Provider 异常文本
  possibleCauses: string[];       // 明示“可能”，不假装已确定根因
  suggestedActions: Array<{id:string; label:string; target:string}>;
  helpTopicId: string;
  correlationId?: string;         // 经脱敏且不包含秘钥的追踪索引
  verifiedAt?: string;            // 未验证时必须缺省
}
```

**三道保密防线**：Rust/provider 对外返回安全码与脱敏上下文；前端只使用固定可信模板；Toast/日志/导出/错误上报不记录 Secret、完整 Authorization、带查询签名的 URL 或剪贴板敏感数据。诊断词条既解释“已知事实”，也解释“尚未验证”。

### 4.4 错误恢复标准例子

- Bucket 名错：本地标红、给格式示例、聚焦字段；如远端 NoSuchBucket，提醒核对账号、桶及辖区，不直接断言一定拼错。
- AccessDenied：描述当前操作被拒绝，提示核对**目标桶范围**和本次所需权限；不要求升级管理员权限。
- Endpoint/DNS：检查账号、辖区、网络代理；当前 R2 默认辖区后端不支持 EU/US/FedRAMP 专用 Endpoint，必须明确显示“当前软件不支持”，不能给出无效修复按钮。
- 任务部分成功：区分成功与失败副本；若先前提交状态不确定，禁止无条件整批重试。
- 远端删除：预先说明云端文件与本地资源记录的影响边界；结果不确定时应先刷新并核对对象是否仍存在。

## 5. 情境教程与首用引导（不是第二套静态帮助中心）

### 5.1 三层帮助

1. **就在字段旁**：术语解释、输入示例、权限风险、一键定位正确设置区域。
2. **与错误绑定**：输入/远端检测失败后自动显示“已确认信息 / 可能原因 / 下一步 / 返回这里”。
3. **用户主动打开的任务教程**：从“第一次发布图片”“找回失败任务”“复制私有临时链接”等任务启动；逐步操作，可跳过、返回、重新开始、关闭。

### 5.2 实现骨架（概念接口）

- `GuideRegistry`：本地版控教程清单，键为 `topicId` + 版本号，含入门场景、步骤、前置条件、安全等级、建议动作、退出条件。
- `GuideLauncher`：从空状态、错误消息、帮助菜单、字段提示触发。
- `GuideProgress`：只存非敏感进度和最后一次界面位置；重启可按用户意愿恢复。**不能存密钥、原始错误、签名 URL**。
- `GuideDock`：优先非阻塞侧边帮助，狭窄窗口可转换为抽屉；临时出现时不得夺走用户表单的焦点。
- `ActionAnchor`：只聚焦实际存在且可操作的目标。导航前后保存当前对象 ID/路径并恢复；锚点丢失时给可用回退入口，不展示假的“已为您修复”。
- `ProblemResolver`：通过 SafeProblem 的 `helpTopicId` 选择教程；不允许根据非脱敏 Provider 文本直接拼模板或外部链接。

### 5.3 首发五篇任务教程（按业务优先级）

| 主题 | 成功验证 | 最低异常路径 |
|---|---|---|
| 第一次连接并发布图片 | 正确目标、任务确认、资源可核对 | 没有云连接；配置错误；入队≠成功 |
| R2 连接排错 | 桶名/账号/用途/最小权限核查 | 连接被拒、Endpoint 不支持、写入测试取消 |
| 找到资源并分享 | URL 类型正确、复制可反馈 | 私有链接过期、公网地址不存在 |
| 处理失败任务 | 有明确失败对象与下一步 | 部分成功、无法安全重试、网络未知 |
| 管理远端文件 | 选择对象与目录、执行后可核对 | 批量删除取消、移动冲突、恢复失败 |

**教程质量验证**：新用户没有外部资料也能识别“下一步”；在错误发生时能恢复到原对象/字段；不因教程取消而保存、上传或删除任何东西。

## 6. 技术重构架构：渐进替换，业务层不大改

### 6.1 建议模块结构（实施目标，不是当前真实目录）

```text
apps/desktop/src/
  ui/{layout,controls,feedback,dialogs,object-inspector}/
  features/{publish,assets,gallery,tasks,storages,plugins,settings}/
  guidance/{registry,GuideDock,GuideLauncher,GuideProgress}/
  diagnostics/{safeProblem,mapper,ProblemResolver,redaction}/
  state/{navigationContext,transientSelections}/
```

- `AppShell` 与页面级布局建立标准模板：`PageHeader / ObjectToolbar / Workspace / Inspector / RecoveryPanel`，覆盖加载、空、成功、失败、部分成功、未知状态。只抽共享模式，不把各页业务强行统一成一个巨型组件。
- React Query 继续负责异步资源数据；Zustand 仅保留导航、需要跨页恢复的 UI 上下文、全局对话框等。缓存失效按后端真实 mutation 成功触发，**不能用纯 UI “成功”直接写状态**。
- 首批保留七页的条件挂载；是否换路由由“状态回归”和深链接需求决定，不在 UI-01 里同时引入路由大迁移。
- 复杂 SettingsPage 先按业务域拆出纯显示区，再逐步拆可测试的表单/命令适配层，不改 Rust 数据格式、迁移状态机与权限。
- 云端故障的稳定契约优先做**后端只输出安全代码与脱敏上下文**的审计；新增只读探针必须单独技术方案和权限验证，不趁界面重构加入静默写入调用。
- 教程内容允许纯本地静态资源离线使用；“AI 排错”若未来引入，必须明确模型可访问的数据范围和是否联网，默认不上传错误日志或凭据。

### 6.2 视觉 Tokens 与交互状态

- 复用现有主题 CSS 变量，新增 Tokens 前先盘点冲突：色彩、字号、字重、间距、边框、半径、阴影、密度、动画。
- 三种主题分别检查：亮色/深色/强调色对比；拒绝“暗色模式只是反转颜色”以及部分面板不响应主题。
- 控件统一 `default / hover / focus / disabled / loading / error / success`；图标按钮必须有可访问名称和操作范围提示。
- 既有确认框复用，危险操作使用对象清单（影响哪些远端对象、是否可恢复、是否影响已发布链接），默认焦点放取消。

## 7. G0—G3 全链路验收规则

| 门 | 要交付的证据 | 未达门时的处理 |
|---|---|---|
| **G0 场景与边界** | 真实用户任务清单、对象/风险地图、主路径和失败路径、现有功能对照 | 禁写新页面代码，先补任务和业务事实 |
| **G1 信息架构** | 七页低保真稿、组件/对象关联图、任务 walkthrough、设计决策记录、完整 `project.taskui.json` strict PASS | 不把漂亮截图等同于可执行设计 |
| **G2 交互与状态** | React + TypeScript/Vite 构建、单元/组件/浏览器自动化，空/加载/错误/未知/取消/重复提交及权限状态的真数据验证 | 按失败文件修复，严禁用假成功状态绕过 |
| **G3 目标端真实验收** | Windows Tauri 原生窗口、1366×768/1024×768/640×480、100/125/150% 系统 DPI，键盘/弹窗/焦点/拖放/长文件名/中文/深色主题；重要流程完成记录 | 缺证据写 HOLD，不用 Edge 模拟替代原生 |
| **发布 G4+（独立）** | NSIS/MSI 安装卸载与版本升级/回滚、私有 R2 protected E2E、权限保密与恢复演练 | 即使 TaskUI G3 通过，也不自动取得正式 Release 授权 |

**自动化与人工证据分账**：CI PASS、Edge 浏览器测具 PASS、Windows Tauri 真实 GUI PASS、Cloud Provider 真实 E2E PASS 四种结论必须分列、逐 commit/工件引用；缺一不冒充另一项。

### 7.1 必测用户任务

- T1（首用）：全新状态 → 配云端 → 回发布 → 上传 → 查看任务 → 在资源验证结果。
- T2（日常）：已有大量资产 → 按文件名筛选 → 选对象 → 公开复制或私有临时链接 → 验证反馈。
- T3（排障）：制造安全的模拟权限拒绝 → 识别阻塞项 → 跳到对应配置 → 返回任务 → 根据重试安全级别恢复。
- T4（图库）：跨目录浏览 → 预览/下载 → 移动/重命名 → 明确确认永久删除；批量模式分开测试。
- T5（迁移/进阶）：仅预览导入 → 检查映射冲突 → 用户批准激活 → 回滚/恢复指引。

每条至少覆盖：首次空状态、真实内容、网络失败、权限不足/未知、取消和返回；不适用场景写“不适用及原因”。

### 7.2 质量目标（**拟定验收阈值，尚无测量结果**）

- 关键流程中没有“死按钮”、遮挡焦点、无法到达的子页面；0 个未经允许的写入、删除、重复提交或凭据/签名泄漏。
- 每个危险操作：先清楚展示对象、数量、影响范围与撤销/不可撤销信息；取消后远端 mutation 调用计数为 0。
- 每个关键错误：用户能看到已确认事实、下一步和明确的不可验证事项；失败时输入保留，帮助关闭后仍能返回位置。
- 招募至少 5 名首次接触镜云或同类工具较少的测试者，完成五类任务；期望 ≥4/5 能在不求助外部教程的情况下完成首用基本任务，并逐个记录卡点。样本太少只作产品启发，**不作统计显著性推断**。
- 不以“按钮数量减少”“平均点击次数”单独判定体验更好。对安全确认流程，必要步骤增加是合理的。

## 8. 风险账本与不碰清单

| 风险 | 阻断方式 | 对应范围 |
|---|---|---|
| 资源索引与远端对象混为一谈 | 双实体保持 API/视觉概念分离，跨页只用已确认关联 ID | 资源 / 图库 |
| 将连接成功视为公开或私有权限证明 | 公开/私有状态必须标注“已验证/未验证”和验证方式 | 云端 / 分享 |
| R2 `test_connection` 写临时对象 | UI 告知并确认；只读 API 必须另立专题 | R2 / 测试连接 |
| 后端错误、Toast 或日志泄露密钥 | Rust 安全错误码 + 前端固定文案 + 负例测试 | 全局诊断 |
| 多窗口/切页上下文丢失，或批量选择危险遗留 | 按范围持久化可恢复状态，跨桶/账号时重置危险选择 | AppShell / 全页面 |

| 只做截图、不做原生系统 DPI 验收 | Windows GUI G3 独立门禁，不用 DPR 模拟偷换 | 所有页面 |
| 多 Agent 同时改共享壳层导致冲突 | 一个 PR 一个语义批次；共享合同先冻结，分支隔离，交叉只读评审 | 工作流 |
| 凭证/真 R2 测试顺手进入开发 CI | protected environment 与临时专用桶隔离，必须显式授权 | 安全 / 发布 |

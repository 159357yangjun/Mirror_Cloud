# UI-01｜镜云全软件七页线框与共享交互合同（G1 候选）

> 2026-10-19，**设计审查候选**。基于 UI-00 实际七页审计及 Edge 源码同 SHA 截图：`docs/ui/UX00_SEVEN_PAGE_SOURCE_AUDIT_2026-10-19.md`。严格 Schema 校验通过不代表 G0 用户任务回放/G3 Windows 人工完成。
> 本文件是七页低保真交互说明，**不包含需要真实后端实现的“假按钮”或演示云成功状态**，还未修改 React/Rust。

## 1. 导航与一致布局

保留 7 个当前真实入口与现有 PageKey，不新增伪「工作流」第八页，也不预先强制压缩成 6 页。侧栏全宽 220px；窄窗变图标轨时保证 title/aria-label/焦点、可滚动到主操作。全局唯一“快速发布”。标题统一为一句话“页面是什么 / 可以完成什么”，旁边只显示当前主动作；工具栏以对象为中心。

```text
┌───────────── NAV 220 / compact rail ──────────────┬──────────── CONTENT ────────────────────────┐
│ 镜云 / 快速发布                                    │ 页面标题 · 当前目的            [唯一主动作]    │
│ 发布  资源  云端  图库  任务  插件  设置             │ [对象筛选 / 当前步骤 / 错误与恢复]              │
│ 当前项 aria-current + focus                       │ ┌──────── 主工作区 ────────┐┌── 选中对象 ───┐ │
│ 教程 / 皮肤 / 版本                                 │ │ 实际列表/编辑/图像/任务   ││ 细节/风险/动作│ │
│                                                    │ └───────────────────────┘└──────────────┘ │

```

## 2. 七页线框（真实功能 → 信息层级，不是绘图假功能）

### S1 发布（T1）

```text
[发布] 选择图片并确认发布去向                              [唯一主动作：选择文件]
┌──────── 图片输入（拖放 / 文件 / URL / 剪贴板）───────┐ ┌─ 当前发布目标 ───────────┐
│ 初次无云端：解释原因 → 导航到云端 → 返回当前流程     │ │ 已确认的 storage/group ID│
│ 已有图片：复用 UploadDialog 的文件/目标/风险核对     │ │ 只能展示实际 API 配置     │
└────────────────────────────────────────────────────┘ ├─ 输出偏好（摘要/修改）──┤
[最近发布] [最近任务]                       [查看全部]     └───────────────────────────┘
```

主行为：上传入队不是成功；无默认目标时引导配置，不能创建假已连接；不复制现有 UploadDialog 内部提交链。局部失败进入实际任务中心验证。

### S2 资源（T2）

```text
[资源] 已发布资源索引                                  [发布新图片]
[搜索已发布记录] [按部署状态筛选] [视图切换]         (URL 公开类型说明)
┌─────────────── 已发布资源列表/卡片 ─────────────────┬─ 资源详情（选择后）─┐
│ 每行仅保留预览、名称、部署状态、基础复制动作           │ 大图 / 文件名/时间    │
│ 对象级状态：已记录、部分部署、结果未知、已确认          │ Deployment 实际副本   │
│ 点击对象 → 右侧显示真实副本与安全的修复能力           │ 公开/私有限时分享    │
└─────────────────────────────────────────────────────┴──────────────────────┘
```

Asset 代表本地发布索引，右侧 Deployment 只显示后端事实；不得从远端文件名反推已发布记录；私有链接要明确有效期和“持有链接可访问”的安全提示。

### S3 云端（T1/T5）

```text
[云端] 管理连接、存储组和真实目标                       [新增存储]
[默认发布目标] [存储组摘要，按需展开]
┌──────────── 连接列表 ───────────────────────────────┬─ 当前连接诊断 ─────────┐
│ Provider / 连接名 / 最近检测结果与时间               │ L0 本地输入预检        │
│ [测试连接] 仅在告知真实副作用并取得授权后执行          │ L1 真只读（若后端存在）│
│ 点击 → Provider 专用逐步向导                         │ L2 临时写入需用户授权  │
└─────────────────────────────────────────────────────┴────────────────────────┘
```

PR #40 为**并行 Draft**，不能认为已纳入集成；R2 现有测试探针包含 write/stat/delete，不能叫只读。连接通过、匿名访问被拒、图片公开链接可用均是不同结论。

### S4 图库（T4）

```text
[图库] 真实云端文件                                     [选择存储] [刷新]
[面包屑 / 上级] [目录 / 搜索] [网格 / 列表] [可见/已选数量]
┌──────── 目录/文件主视图 ────────────────────────────┬─ 单对象预览及动作 ─────┐
│ 一个存储范围内的目录树/远端文件列表                   │ storageId + exact path│
│ 选择文件时显示批量工具栏，换 Bucket 清掉危险选择       │ 预览/下载/重命名/移动  │
│ 操作排队后显示任务 ID，不能显示“文件已完成移动”        │ 永久删除二次确认范围  │
└─────────────────────────────────────────────────────┴────────────────────────┘
```

StorageEntry 不是 Asset；删除必须明确当前桶、目录、对象数量、可否恢复，取消 mutation 调用计数应为 0，异步作业核验真实任务结果。

### S5 任务（T3）

```text
[任务] 看懂任务执行和恢复                               [刷新]
[全部] [进行中] [失败/部分成功] [已完成] [未知]
┌────────────── 任务列表 ──────────────────────────────┬─ 选中任务的证据 ───────┐
│ 标题/类型/状态/时间/进度 ≠ 完成确认                   │ 已完成项/失败项/未知项│
│ 状态不确定 → 显示“先检查结果”，禁用无脑重复提交        │ 已证实与可能原因分开  │
│ 安全重试只针对确实允许重试的项                         │ 修复跳转/检查/安全重试│
└─────────────────────────────────────────────────────┴────────────────────────┘
```

任务状态源为 Rust 后台，不能按前端动画进度写任务完成；不暴露原始云凭据/签名信息；未经安全判定不得新增重试行为。

### S6 插件和 AI（T6）

```text
[插件] 安装、权限和运行效果                              [可选：访问插件市场]
┌──── 已安装插件（首屏） ────────────────────────────┬─ 插件权限/配置详情 ─────┐
│ 实际状态 / 可用 hooks / 上次运行与失败                 │ [读取资源] [联网] [密钥] │

├──── 执行记录（可展开） ─────────────────────────────┤ [撤权][JSON高级配置]     │
```

弹窗不得默认授予过宽权限，必须有撤销反馈；AI 服务可能联网，不可默认上传用户图片或诊断日志。

## 3. 共享操作与统一状态合同（拟订接口，不是现有 API）

- PageHeader：页面标题、对象级唯一主操作、必要时状态。
- ObjectToolbar：仅提供当前列表的搜索/筛选/排序；显示实际筛选结果和空态。
- ObjectInspector：从确切 `kind + id + storageId/path` 获取细节，脱离对象时关闭，不允许用同名字符串关联不同语义。
- SafeProblem：固定字段 `kind / operation / severity / outcome / retrySafety / safeSummary / possibleCauses / actions / helpTopicId`；原始 Provider 文本只能在已核实脱敏的后端诊断通道处理。
- GuideLauncher + GuideDock：可以从错误、字段或帮助入口激活，保留来源页面/对象/字段；只存非敏感进度，不允许自动写入、上传、删除。
- ConfirmDialog：写入、删除、批量、升级操作必须披露作用对象和范围；Tab/Shift+Tab/Escape、默认取消、焦点归还统一。
- 状态词汇：未配置 / 读取中 / 空 / 等待 / 处理中 / 失败 / 部分成功 / 结果未知 / 已核实。禁止“请求被接受”显示“发布完成”。

## 4. 页面与导航上下文保存范围

| 范围 | 应保留的无害上下文 | 必须清理或重新确认的敏感/危险状态 |
|---|---|---|
| 发布 → 云端 → 发布 | 来源类型、未提交的本地表单步骤（仅内存）；实际已选目标 ID | 已过期文件句柄、从旧目标继承的密钥、暗中提交 |
| 资源 ↔ 图库 | 已选 Asset ID、真实 Storage ID + remotePath（若已证实） | 仅靠文件名猜测的映射 |
| 图库切页/切桶 | 原 Storage ID + 当前目录/筛选（非敏感） | 批量选中路径、未完成永久删除确认 |
| 任务 → 配置 → 任务 | 任务 ID、错误类别、返回入口 | 安全重试授权不能复用；未知状态先核对 |
| 任一页面 → 帮助 → 返回 | 页面 ID、对象 ID、字段锚点 | API token/secret、签名 URL、原始响应、剪贴板内容 |

任何“原位置恢复”均须先检查当前对象仍存在、路径仍有效，失效时显示“回到对象列表”而不是假装恢复成功。

## 5. 跨页完成轨迹（G1 task walkthrough）

- T1 首用：发布无目标 → 云端连接并核对真实副作用 → 返回发布 → 现有 UploadDialog 核对 → 后台 Task 真实完成 → Asset/Deployment 验证。若云端失败，保留输入并回对应字段；若任务未知，停在核对而非重复上传。
- T2 分享：资源搜索 → 选对象 → 非私有且 URL 真实存在时复制；私有则另走预签名链接并明确时效与访问范围。公开 URL 不存在时显示缺失，不提供无效复制。
- T3 任务恢复：任务过滤失败/部分成功 → 详情区显示失败项及依据 → 修复连接/凭据 → 返回原 Task → 复核成功副本 → 只重试允许重试的失败项。
- T4 远端文件：图库选择明确 storageId 和 path → 操作对象 → 危险操作先列明精确作用范围 → Cancel 0 调用；已排队时跳任务确认，不能直接宣称已删除。
- T5 云端：识别每个 Provider 的真实 Endpoint 能力 → 明确 L0/L1/L2 检查；L2 需用户授权。
- T6 插件：选择插件 → 阅读每项权限理由 → 审核启用 → 查看执行记录 → 可撤销权限。
- T7 输出：进入设置当前组 → 修改输出格式 → 回发布/资源复制 → 以真实结果核对。
- T8 迁移：只读导入预览 → 映射检查 → 风险确认 → 人工批准激活 → 结果核对，失败可检查分步证据。
- T9 升级：检查 → 下载 → 用户启动安装 → 原生版本验证 → 回退门禁，任何阶段不得提前标记成功。
- T10 教程：从字段/报错打开 → 展示相关步骤（不复制密钥）→ 关闭后回实际对象/输入位置；锚点失效提供回退。

## 6. 决策记录与 G1 审查阻塞

| 设计决策 | 原因 | 未采用方案 |
|---|---|---|
| 保留七顶层页，不强行六页 | 对应现有 PageKey 与真实页面，各有明确对象语义 | 先改导航数量再补后端 |
| 把资源和图库**联系**而非**合并** | Asset 与 StorageEntry 数据源不同 | 从相同文件名推断对象身份 |
| 先抽共享组件合同，不大重写 Rust | 业务迁移、权限变更风险高 | 直接改 API、迁移或安全门禁 |
| 错误以对象内联为主，全局 Toast 简短 | 避免遮挡恢复按钮与泄露原始错误 | Toast 展示完整 Provider exception |
| 教程只引导真实存在的操作 | 使用户按真实任务完成并有返回路径 | 生成自动修复按钮但无对应后端 |
| G1 严格校验是结构校验，不是可用性结论 | 原生系统 DPI/真实新手测试仍缺 | 以 Schema PASS 取代 G3 或真实 R2 E2E |

**待审要点**：十任务频率与新手步骤预算需要用户观察修正；七页详情侧栏在 640×480 的收纳位置需 Windows 原生 DPI 走查；安全错误输出合同必须先由 Rust/Provider 完成脱敏审计。

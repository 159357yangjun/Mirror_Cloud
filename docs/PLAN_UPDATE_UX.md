# PLAN：更新入口降级 + 启动自动检查（C 方案）

日期：2026-10-06 ｜ 前置：v1.4.8 已发布（Release id 404652713）｜ 状态：**等批准，未动代码**

## 用户点名的两件事

1. 「关于与更新」现在是设置页末尾一整张大卡——低频功能穿了高频功能的衣服，布局乱。入口可以不显眼，但不能乱堆。
2. 问"有没有自动检查更新"——**现状没有**（`checkForUpdates` 全仓唯一触发点是那个按钮的 onClick），要补。

## 设计（三块，YAGNI 裁剪后）

### A. 后端：结果缓存进 settings（新命令 `get_update_status`）

- 现有 `check_for_updates` 不动（手动按钮继续用它）。新增一条查询命令：读 settings key `update.lastCheck`（上次检查的结果 JSON + checkedAt），返回给前端；**它不发网络请求**。
- 写侧：`check_for_updates` 成功返回前顺手把结果+时间戳写进该 key（best-effort，写失败只 warn，不让一次成功的检查因为存不下而报错）。
- 为什么缓存在后端而不是 localStorage：CLI/Local API 通道之外，重启后、换设备登录同一数据目录都能看到；且和 step 4 的 `reconciliation.lastSweep` 同族同形，门能复用一套写法。

### B. 前端：启动静默检查，每天最多一次

- AppShell 挂载时：先 `get_update_status` 拿缓存 ⇒ 若 `checkedAt` 距今 <24h 或有新版待提示，直接决定要不要亮圆点，**不发请求**；过期才后台跑一次 `checkForUpdates`。
- **失败完全静默**（无 toast、无红字、不重试当次会话）：这是开机路径，一个查不到新版的网络抖动不该打扰任何人。错误只在手动点按钮时才显示（保持现状）。
- 有 `updateAvailable` ⇒ 侧栏底部版本行右侧亮一个琥珀色小圆点（10px，带 title「发现新版本 v1.4.9，点击去设置」，点了跳设置页并滚到更新卡）。无新版/没查过 ⇒ 什么都不亮。
- 一天一次的判据用缓存时间戳本身，不另设计数器。

### C. 布局：大卡收成一行 + 就地展开

- 「关于与更新」卡头保留（标题+说明文），**主按钮降为小号描边**；未检查过时不再占整屏灰底详情块。
- 检查结果仍就地展开成现有灰底块（下载/安装流程一字不动——sha256 门禁链是 G1 的成果，本次纯视觉与入口层级调整，**安全路径零改动**）。
- 版本号改用刚接好的 `__APP_VERSION__`（上一笔已注入），卡头文案「当前 v1.4.8」。
- 侧栏 footer 那行加圆点位（B 的落点），其余不动。

## 门禁与测试（本仓规矩）

- 新门 ≥5 条同笔：`update.lastCheck` key 独立于其他 settings key；缓存读命令注册且前端 invoke 对账（contracts 自动管）；AppShell 里"缓存优先、过期才发请求"的顺序谓词；失败静默面（catch 分支不得含 toast/error state 写入）；圆点仅由 updateAvailable 驱动。
- 变异 ≥3 条走 userflow-src 通道（摘缓存短路 / 给静默 catch 塞报错 / 圆点改恒亮）。
- 本地跑：fmt、tsc -b、user-flow、project_state --verify、指纹/shape 重签。**Rust 编译与 test 面只有 CI 作证**（本机 link 死，§25 在册）。
- 浏览器门（pages/visual/settings-guard）起 dev server 跑一遍确认布局改动没踩对比度/触达尺寸红线。

## 明确不做（说了也算数）

- 托盘角标、系统通知弹窗、强制更新、每周多次检查——都没点名，不加。
- 自动下载更不做：发现→展示→人点下载，这条链一步不缩短（sha256 校验后才许启动安装器的纪律不变）。
